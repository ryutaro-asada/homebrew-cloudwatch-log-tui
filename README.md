# homebrew-cloudwatch-log-tui

Homebrew tap for [cloudwatch-log-tui](https://github.com/ryutaro-asada/cloudwatch-log-tui).

## Install

```sh
brew tap ryutaro-asada/cloudwatch-log-tui
brew trust ryutaro-asada/cloudwatch-log-tui
brew install cloudwatch-log-tui
```

Recent Homebrew versions refuse to load formulae from non-official taps until you trust them
(`Refusing to load formula ... from untrusted tap`). `brew trust` records the tap in
`~/.homebrew/trust.json` (or `$XDG_CONFIG_HOME/homebrew/trust.json` if `XDG_CONFIG_HOME` is set).
To trust only this formula instead of the whole tap, run
`brew trust --formula ryutaro-asada/cloudwatch-log-tui/cloudwatch-log-tui`.

## Upgrade

```sh
brew update && brew upgrade cloudwatch-log-tui
```

## Maintenance

`Formula/cloudwatch-log-tui.rb` is regenerated by `scripts/update-formula.sh`, which downloads the
`darwin-amd64`, `darwin-arm64`, and `linux-amd64` release archives and writes their SHA256 hashes
into the formula.

- **Update Formula** (`.github/workflows/update-formula.yml`) runs daily at 00:00 UTC.
  `scripts/check-version.sh` compares the latest GitHub release with the formula version, and if a
  new release exists the workflow opens a pull request with the updated formula. It can also be run
  manually with an optional `version` input.
- **Direct Formula Update** (`.github/workflows/direct-update.yml`) runs on `workflow_dispatch`
  with a required `version` input and an optional `skip_pr` input. By default it opens a pull
  request; with `skip_pr` it commits directly and opens a notification issue. It also
  runs on a `cloudwatch-log-tui-release` `repository_dispatch` event, which commits directly.
